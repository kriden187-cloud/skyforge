# Конвейер обработки снимков JWST и Hubble

Oct 18, 2026 · @Denis

## Цель и принципы

Строим консольный инструмент `skyforge`, который по названию объекта скачивает откалиброванные кадры JWST или Hubble из архива MAST и собирает из них цветное изображение. Один запуск, один YAML-конфиг, на выходе PNG и 16-битный TIFF плюс отчёт со всеми промежуточными картинками. Работает на домашнем ПК с RTX 5060 Ti 16 ГБ, без облака.

Принципы, под которые пишется весь код:

- **Каждый этап оставляет картинку.** Скачал — превью каждого фильтра. Выровнял — наложение в шахматку. Растянул — гистограмма до и после. Ошибку конвейера видно глазами, читать код не нужно.
- **Всё воспроизводимо.** Один конфиг описывает объект, фильтры, параметры растяжки и раскраски. Тот же конфиг через месяц даёт тот же результат. Понравившаяся обработка сохраняется как файл, а не как память о ползунках.
- **Сырые данные неприкосновенны.** Скачанные FITS лежат в кеше и никогда не меняются, вся работа идёт в копиях. Повторный запуск не качает заново.
- **Сначала грубо, потом точно.** Параметры подбираются на уменьшенной в 4 раза копии за секунды, полное разрешение считается один раз в конце.
- **Один этап — одна команда.** Конвейер можно запустить целиком или остановиться на любом шаге и посмотреть, что получилось.

## Архитектура

Шесть команд, которые идут одна за другой и передают друг другу массивы через `data/work/`. Каждая из них отдельно запускается из консоли, и каждая оставляет в `out/` картинку, по которой проверяется результат.

```
MAST / data/inbox
      │
  fetch ────────► data/raw/  (только чтение)
      │
  inspect ──────► inspect_sheet.png       превью каждого фильтра
      │
  align ────────► align_check.png         шахматка двух фильтров
      │             data/work/<объект>/bin<N>/aligned/
  stretch ──────► stretch_hist.png        гистограммы до и после
      │             data/work/.../stretched/
  compose ──────► compose.png             цветная сборка
      │             data/work/.../composite.npy
  finish ───────► <объект>.png, <объект>.tif, finish_zoom.png
      │
  report ───────► report.html             все стадии на одной странице
```

Данные идут сверху вниз, превью уходят вправо. Этапы с `align` по `finish` читают параметры из одного YAML, поэтому понравившаяся обработка воспроизводится из файла.

## Стек и структура проекта

Чистый Python без тяжёлых графических программ: всё, что делает Siril или PixInsight, здесь делают библиотеки, а результат проверяется по картинкам в папке `out/`.

| Задача | Библиотека | Зачем именно она |
| --- | --- | --- |
| Поиск и скачивание из MAST | `astroquery` | Официальный клиент архива, понимает прокси через переменные окружения |
| Чтение FITS, WCS, единицы | `astropy` | Стандарт в астрономии, умеет memmap для больших файлов |
| Совмещение кадров по координатам | `reproject` | Переводит кадры разных фильтров на одну сетку по WCS из заголовков |
| Растяжка и цвет | `astropy.visualization`, `numpy` | asinh, Lupton RGB, процентили |
| Денойз, резкость, экспорт | `scikit-image`, `Pillow`, `tifffile` | 16-битный TIFF без потерь |
| CLI и конфиг | `typer`, `pydantic`, YAML | Команды с автодокументацией, конфиг с проверкой полей |
| Отчёт | `jinja2` + HTML | Все стадии на одной странице, открывается в браузере |
| Тесты | `pytest` | Крошечный синтетический FITS, чтобы прогон занимал секунды |

Окружение: Python 3.12, менеджер пакетов `uv`, Windows 11. Никакого Docker на этом этапе: он добавляет слой, который мешает смотреть картинки.

Папки:

```
skyforge/
  src/skyforge/
    cli.py          команды: fetch, inspect, align, stretch, compose, finish, run, report
    fetch.py        MAST: поиск, фильтрация продуктов, скачивание в кеш
    inspect.py      заголовки, превью, таблица фильтров
    align.py        общая сетка, репроекция, обрезка до пересечения
    stretch.py      фон, клиппинг, asinh/log, нормализация 0–1
    compose.py      фильтр → цвет, смешивание, баланс
    finish.py       денойз, резкость, экспорт TIFF/PNG, метаданные
    report.py       HTML-отчёт по всем стадиям
    config.py       схема YAML-конфига
  configs/          один YAML на объект: ngc3132.yaml, pillars.yaml
  data/raw/         кеш скачанных FITS, никогда не редактируется
  data/work/        промежуточные массивы по стадиям
  out/<объект>/<дата-время>/   итог, превью, отчёт, копия конфига
  tests/
```

Пример конфига, который задаёт всю обработку:

```yaml
target: "NGC 3132"
mission: jwst
instrument: nircam
filters: [F090W, F187N, F212N, F356W, F405N, F470N]   # тот же набор, что в пресс-релизе
calib_level: 3            # готовая мозаика со всех экспозиций, а не отдельные кадры уровня 2
reference: F470N          # кадр, к сетке которого приводятся остальные
bin: 4                    # уменьшение для подбора параметров; 1 для финала
stretch:
  method: asinh
  black: 0.5              # процентиль фона
  white: 99.8             # процентиль ярких деталей
  a: 0.02                 # сила asinh
color:
  mode: wavelength        # auto: короткие волны → синий, длинные → красный
  saturation: 1.2
  overrides: { F187N: "#ff8040" }   # ручное переопределение отдельного фильтра
finish:
  denoise: 0.3
  sharpen: 0.5
  north_up: true
```

## Ограничения железа и сети

Настольный ПК с RTX 5060 Ti 16 ГБ снимает вопрос мощности: мозаика NIRCam до 8000×8000 пикселей в float32 занимает 256 МБ на фильтр, и пять фильтров с копиями укладываются в оперативную память целиком. Узким местом остаётся сеть, а не железо.

| Ограничение | Что делаем |
| --- | --- |
| Доступ к MAST из России | `astroquery` ходит через `requests` и уважает переменную `HTTPS_PROXY`. Прокси задаётся в `.env`, а не в коде. Скачивание докачивает оборванные файлы и проверяет размер. Запасной путь: папка `data/inbox/`, куда кладёшь FITS, скачанные вручную с портала, и конвейер подхватывает их без сети. |
| Диск | Один объект JWST — от 0,5 до 5 ГБ сырых данных. Скачиваются только фильтры из конфига, а не вся программа наблюдений. Кеш чистится командой `skyforge cache prune`. |
| Скорость подбора параметров | Памяти хватает, но крутить растяжку на полной мозаике всё равно долго. Режим `bin: 4` остаётся для перебора вариантов за секунды, финал считается на `bin: 1`. |
| Видеокарта | Репроекция и растяжка идут на процессоре, библиотеки под GPU не заточены, и это нормально. Видеокарта пригодится в фазе качества: нейросетевой денойз и деконволюция через PyTorch с CUDA, а также выделение звёзд отдельно от туманности по типу StarNet. 16 ГБ видеопамяти хватает на целый кадр без нарезки на плитки. |
| Время счёта на полном разрешении | Репроекция большой мозаики занимает минуты и делается один раз на объект, результат кешируется в `data/work/`. Растяжка и цвет пересчитываются за секунды. |

## План по фазам

Шесть фаз, каждая заканчивается картинкой, по которой видно, сработало или нет. Первые две дают готовое изображение за одни выходные, остальные можно делать по настроению.

**Фаза 0. Первый контакт с данными** (один вечер)

- Окружение через `uv`, каркас проекта, правила для агента.
- `skyforge fetch "NGC 3132" --mission jwst --instrument nircam`: поиск в MAST, список доступных фильтров, скачивание `_i2d.fits` уровня 3 в кеш. Суффикс i2d носят и отдельные экспозиции уровня 2, поэтому фильтруем по calib_level == 3.
- `skyforge inspect`: таблица фильтров с длиной волны, размером и экспозицией плюс чёрно-белое превью каждого.
- Приёмка: в `out/` лежат пять превью, и на каждом узнаётся туманность Южное Кольцо.

**Фаза 1. Первое цветное изображение** (выходные)

- `align`: репроекция всех фильтров на сетку опорного, обрезка до общего поля. Превью: шахматка двух фильтров, звёзды совпадают на границах клеток.
- `stretch`: вычитание фона, asinh, нормализация. Превью: гистограмма до и после, картинка каждого фильтра.
- `compose`: три фильтра в RGB по длине волны.
- Приёмка: своё изображение рядом с официальным пресс-релизом. Цвета могут отличаться, структура должна совпадать.

**Фаза 2. Конфиг и отчёт** (неделя по вечерам)

- Все параметры переезжают в YAML, `skyforge run config.yaml` прогоняет всё целиком.
- Больше трёх фильтров: каждому назначается оттенок по длине волны, слои смешиваются.
- Режим `bin: 4` для быстрого перебора и `skyforge sweep`, который строит сетку из 9 вариантов растяжки на одном листе.
- HTML-отчёт со всеми стадиями, параметрами и копией конфига.
- Приёмка: меняешь одно число в YAML, перезапускаешь, видишь разницу в отчёте. Тот же конфиг дважды даёт одинаковый файл.

**Фаза 3. Качество и Hubble** (две недели)

- Звёзды: укрощение выжженных ядер и дифракционных лучей JWST, разделение звёзд и туманности для отдельной обработки.
- Градиенты фона, швы мозаики, денойз и деконволюция на GPU.
- Hubble: файлы `_drc`, другие единицы и масштаб пикселя, следы космических лучей.
- Приёмка: один объект собран и из JWST, и из Hubble, оба без видимых швов и артефактов при просмотре 100%.

**Фаза 4. Поиск нетронутых объектов** (неделя)

- `skyforge discover`: наблюдения JWST, у которых недавно истёк срок эксклюзива, с фильтром по инструменту, числу фильтров и площади поля.
- Сверка с галереей пресс-релизов: что уже обработано официально, то в конец списка.
- Приёмка: список из 10 кандидатов с превью, и хотя бы один из них собран до конца.

**Фаза 5. Публикация** (по желанию)

- Экспорт с подписью и указанием источника (NASA, ESA, CSA, STScI, обработка твоя), версии под разные площадки.
- Архив конфигов как своя галерея: каждый YAML — воспроизводимая работа.

## Риски и ловушки

Большинство проблем выглядит как «картинка странная, а код не ругается». Таблица помогает по симптому найти причину и сформулировать задачу для агента.

| Симптом на картинке | Причина | Обход |
| --- | --- | --- |
| Цветные ореолы у звёзд, двоение | Фильтры не совмещены: короткие и длинные волны NIRCam сняты с разным масштабом пикселя (0,031″ и 0,063″) | Репроекция по WCS обязательна даже при одинаковом размере массивов; шахматка в отчёте ловит это сразу |
| Чёрный квадрат или всё белое | NaN на краях мозаики попали в процентили, или перепутан порядок байтов | Все статистики считать через `nanpercentile`, NaN заменять только перед экспортом |
| Туманность плоская, деталей нет | Слишком сильная растяжка или белая точка ниже ярких зон | `sweep` с сеткой вариантов вместо подбора по одному числу |
| Всё зелёное или фиолетовое | У каналов разный уровень фона и яркости | Фон вычитать и нормировать каждый канал отдельно до смешивания, баланс по нейтральному фону |
| Видны прямоугольные швы | Стыки плиток мозаики с разным фоном в самом файле | Выравнивание фона крупной моделью (фаза 3); до того — кадрирование |
| Скачивание обрывается или не начинается | Прокси, таймауты MAST, файлы по гигабайту | Докачка с проверкой размера, папка `inbox/` для ручной загрузки |
| Нужного фильтра нет в архиве | Данные ещё под эксклюзивом авторов программы | `inspect` показывает дату снятия эксклюзива; конфиг допускает неполный набор |
| Hubble выглядит в крапинку | Следы космических лучей в одиночных экспозициях | Брать только `_drc`, где кадры уже сложены; остатки убирает медианный фильтр по маске |
| Результат отличается от вчерашнего при том же конфиге | Скрытый параметр в коде или случайность в денойзе | Тест на воспроизводимость: два прогона дают одинаковый хеш файла |

Отдельный риск — не технический. Агент любит добавлять возможности, и проект легко разрастается до фазы 3, когда фаза 1 ещё не дала картинки. Правило: новая фаза начинается только после приёмки предыдущей.

## Как работать с агентом

Этот документ кладётся в репозиторий как `docs/PLAN.md`, а рядом (локально, вне репозитория) лежат короткие правила, которые агент читает при каждом запуске.

Задачи формулируются по одному этапу и всегда с критерием, который проверяется глазами. Пример для фазы 1:

> Реализуй команду `skyforge align` по docs/PLAN.md. Вход: папка с i2d-файлами и имя опорного фильтра. Выход: массивы на общей сетке в data/work/ и превью out/align_check.png, где два фильтра показаны шахматкой с клеткой 256 пикселей. Критерий: звёзды на границах клеток не смещены. Сначала напиши тест на синтетическом FITS со сдвинутым WCS, потом код.

Проверка каждой задачи складывается из трёх сигналов: тесты зелёные, превью в `out/` соответствует критерию, а повторный прогон даёт тот же файл. Когда картинка не нравится, симптом ищется в таблице рисков и передаётся агенту вместе с самой картинкой: агент умеет смотреть PNG и видит ореолы и швы сам.

## Статус реализации

| Фаза | Состояние |
| --- | --- |
| 0. Первый контакт | Реализовано: `fetch`, `inspect`, inbox, докачка, манифест |
| 1. Первое цветное | Реализовано: `align` (WCS, север вверх, обрезка), `stretch`, `compose` |
| 2. Конфиг и отчёт | Реализовано: `run`, раскраска N фильтров, `bin`, `sweep`, HTML-отчёт, тест воспроизводимости |
| 3а. Качество JWST | Принято (тег `phase-3a`): этап `clean` — пьедесталы плиток по слою CON, гладкая модель фона, заполнение насыщенных ядер; `sweep` по весам фильтров |
| 3а-звёзды | Принято (тег `phase-3a-stars`): `color.star_saturation` — звёзды поля к серому той же яркости, туманность не трогается; `color.lift` заменён на `color.shadows` (больше — сильнее) |
| 3б. Hubble | Не начато |
| 4. Поиск объектов | Не начато |
| 5. Публикация | Частично: подпись и источник пишутся в метаданные PNG/TIFF |

Отступления от плана, сделанные сознательно:

- `finish.north_up` лежит в секции `finish`, как в примере конфига, но применяется на этапе `align`: поворот на север и совмещение делаются одной интерполяцией, а не двумя, и края не теряются дважды.
- Каждая команда, запущенная отдельно, пишет превью в `out/<объект>/current/`, а `skyforge run` — в новую папку `out/<объект>/<дата-время>/`. Так поэтапная отладка не плодит десятки папок.
- `color.blend: average` по умолчанию вместо screen: при шести фильтрах screen сводит туманность в жёлто-белое. Цена — деталь, яркая лишь в 2–3 фильтрах, темнеет; её поднимает `color.shadows` (asinh по яркости после смешивания, оттенок не меняется; больше — сильнее, бывший `lift` с обратной шкалой). Общая растяжка с меньшим `a` тоже поднимает оболочку, но вместе с фоном и стыками мозаики.
- В i2d уровня 3 нет слоя DQ, на который рассчитывала задача про ядра звёзд. Насыщенные и отбракованные пиксели там уже NaN с WHT=0 — по ним и строится маска ядер.
- Стыки мозаики — не градиент, а ступеньки с прямыми краями: гладкая модель по блокам их только размазывает. Поэтому фон выравнивается в два шага: сначала постоянная поправка на каждую область слоя CON (свой набор экспозиций), затем гладкая модель для остатков.
- **Известное ограничение:** наклон фона внутри одной плитки (у NGC 3132 — около 0.8σ в F187N/F212N в левом верхнем углу, виден только при 100% и при shadows сильнее 4). Поправка на область CON его не снимает: нужен skymatch по отдельным экспозициям уровня 2, а это отдельный конвейер. Решено не делать, пока ограничение не вылезет на другом объекте.
- Вуаль вокруг звёзд поля — не фон, а крылья PSF в данных (в основном F356W): отношение «кольцо 12–30 px / фон» около 2 при любом подъёме теней, без подъёма тоже. Оставлена как есть.
- Маска звёзд ищется в самом коротковолновом фильтре (F090W): при объединении по всем фильтрам в неё попадали узлы оболочки и фоновые галактики из длинных волн. Обесцвечивается не весь пиксель под маской, а доля звёздного света в нём: на пустом небе — по итоговой яркости (сереет и ореол), на туманности — по фильтру поиска, где внешней оболочки почти нет. Слабые объекты, видимые только в длинных волнах (вероятно, далёкие галактики), остаются цветными.
- `cache prune` по умолчанию чистит только `data/work/`. Сырые файлы удаляются лишь явным `--raw <объект>` с подтверждением.
