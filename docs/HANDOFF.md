# Skyforge — передача контекста в новый чат

Документ для продолжения работы над Skyforge в отдельном чате. Агенту читать первым, вместе с `docs/PLAN.md` и локальными правилами агента (вне репозитория). Обновлять при закрытии каждой фазы.

## 1. Что это за проект

Skyforge — личный конвейер обработки снимков JWST (и в перспективе Hubble) из сырых данных архива MAST в цветные изображения. Хобби-проект Дениса, не связан с работой. Цели: собирать картинки не хуже пресс-релизов NASA, а дальше — объекты, которых никто красиво не обрабатывал.

- Репозиторий: `D:\AIAgents\Skyforge\`, ветка `master`, Python 3.12 + `uv`.
- Железо: настольный ПК, RTX 5060 Ti 16 ГБ, Windows 11.
- Сеть: MAST ходит через прокси `127.0.0.1:10809`; когда прокси лежит, сборка идёт с `--offline` из кеша.
- Владелец не читает код. Приёмка идёт по картинкам (кропы 100% и ×5), тестам, хешам и отчёту. Любое утверждение агента должно быть подтверждено картинкой или числом.

## 2. Архитектура (как есть)

Этапы: `fetch → build (уровень 2) → align → clean → stretch → compose → finish → report`. Каждый этап оставляет превью в `out/`. Конфиг на объект в `configs/<объект>/`: `base.yaml` + стили через `extends`.

Ключевые решения, которые уже приняты и не пересматриваются без причины:

| Решение | Почему |
|---|---|
| Сборка мозаики из уровня 2 (`_cal.fits`, 120 экспозиций для NGC 3132), а не из i2d уровня 3 | На мозаике уровня 3 рисунок экспозиций уже смешан, ступеньки фона не снимаются ничем (3d, 3e) |
| destripe в системе детектора по 4 усилителям, окно 201 строка, затем по столбцам | Снимает 1/f-полосы, не трогает ореол |
| Астрометрия экспозиций по звёздам i2d (аналог tweakreg); порог — точность сдвига < 0,03 px, не остаток звезды; 4 детектора SW одной экспозиции сдвигаются вместе | Остаток отдельной звезды упирается в центроид на 2 px, не в WCS |
| Веса стека — `VAR_RNOISE`, не `ERR` | В ERR входит шум звезды, ядро теряло вес, поток −2% |
| Растяжка привязана к маскам: `black` по небу, `white` по туманности (`stretch.anchor: masks`) | Очистка фона не должна двигать растяжку |
| Параметр `shadows` (больше — сильнее), `a` оставлен как в astropy (меньше — сильнее) | Путаница с направлением стоила одной ошибочной приёмки |
| Маска туманности: звёзды заменены локальной медианой, диск 71 px, компоненты с насыщенным ядром вне главной исключены | Плашки вокруг ярких звёзд были маской туманности, а не обесцвечиванием |
| Цветовая карта фона `neutral_background: map` (блоки 256 px, только цвет, яркость не меняется), считается по всему кадру | Одна константа на канал не снимала цветные пятна |
| Блочная модель яркости фона — выключена (опция осталась) | Меняла красный фон на зелёные пятна и портила фактуру |
| Кадр `union` с обрезкой до поля, где у каждого канала есть фильтр, верхняя полоса без F470N срезана, `min_exposures_sw: 0` | Совпадение с кадром NASA; правило по экспозициям резало кольцо 150–350 px по периметру |
| Статистика (пороги масок, точки растяжки) — по полю, где есть все фильтры | Расширение кадра не должно менять результат внутри |
| Кропы приёмки заданы в RA/Dec | При смене сетки они пересчитываются сами (ошибка 3g: кропы были сдвинуты на 149×270 px) |
| Два стиля: `measured` (что зарегистрировано) и `showcase` (как у NASA) | Инфракрасного цвета нет, выбор палитры — выбор автора |
| measured: вес F212N 0,25 | Ореол H2 настоящий (корреляция с i2d STScI 0,998), при 0,5 зелёный, при 0,25 оранжевый |
| showcase: веса F212N 0,12, F405N 0,25, насыщенность 1,4, per-filter растяжка, `shadows` по маске туманности | Подобрано sweep'ом с референсом NASA в первой клетке |

## 4. Известные ограничения (записаны в PLAN.md)

- Ступеньки фона на границах числа экспозиций (кольцо по периметру, линия слева, ступенька в кропе `sky`). Причина — 4 исключённые экспозиции F470N и геометрия дизеринга. Лечится только в сведении уровней стека, не обрезкой.
- Наклон фона внутри плитки ~0,8σ.
- Вертикальная полоса в F356W (кроп `sky2`): сдвигается на шаг дизеринга между экспозициями, на небе стоит на месте. Не дефект столбца, причина не установлена.
- Синяя диагональ через центральную звезду в F090W — дифракционный луч, данные.
- Расхождение потока звёзд i2d и экспозиций (F212N ×0,90, F470N ×0,85) — наблюдение, не вывод.
- 29/30 звёзд в допуске FWHM, одна в F470N.
- Лучи ярких звёзд не входят в маску звёзд; на объекте с очень яркой звездой могут вернуться цветные лучи.
- Ядра трёх звёзд с насыщением (центральная, внизу справа, слева в оболочке) — белое пятно 30–40 px; слой звезды до растяжки (`stretch.saturated_stars`) упирается в заполненные ядра clean, выключен (3i).
- Одна звезда поля (x 586, y 62 у верхнего края) с зеленоватым ядром при выключенном обесцвечивании в showcase — принято (3j).
- Небо NASA светлее и ровнее нашего (~6 уровней во всех кропах sky против 0,5–3,2 у нас) — наблюдение, не трогали (3j).
- Внешний ореол showcase обрывается на ~720 px от центральной звезды (край маски туманности): наш / NASA 0,5–0,6 на 800–1150 px. Подъём за маской упирается в неровность фона (3j, п.1).

## 6. Как мы работаем (правила для главного агента)

Эти правила частично продублированы в локальных правилах агента (вне репозитория):

- Фаза начинается только после приёмки предыдущей. Коммит и тег — после приёмки владельцем.
- Каждое задание содержит критерии приёмки, проверяемые глазами по кропам. Метрика подтверждает, но не заменяет.
- Прямая граница на небе любой высоты — не принято, даже если «ниже шума».
- Среднее по туманности не ловит выжигание: всегда фактура (σ в кольце 30–200 px) и кроп `core`.
- Если число в задании (порог, радиус, процент) отрезает больше, чем ожидалось, — остановиться и показать, что отрежет, прежде чем применять. Это правило действует и на задания, которые даёт владелец или консультант.
- Отступление от задания допустимо, если объяснено и показано картинкой.
- Объяснение причины без проверки на данных — гипотеза; в отчёте так и писать.
- Отчёт о фазе: что сделано, что не выполнено и почему, отступления, что решить владельцу (с вариантами), таблица «файл — что на нём должно быть». Коммит — только после приёмки.
- При любой смене сетки кадра кропы пересчитываются автоматически (тест есть).
- Все проверки — на кропах `core`, `edge`, `sky`, `sky2`, `sky3`, `sky4` при 100% и ×5, рядом с baseline и референсом NASA.

## 7. Субагент-приёмщик

Описание субагента-приёмщика (локальный файл агента, вне репозитория; создать, если ещё нет):

```markdown
---
name: acceptance
description: Приёмка фазы Skyforge по картинкам и отчёту. Вызывать после каждой фазы, до коммита и тега. Use proactively when a phase is reported done.
tools: Read, Glob, Grep, Bash
model: opus
---

Ты приёмщик проекта Skyforge. Твоя работа — решить, принята фаза или нет,
и написать, что именно не так. Ты не чинишь код и не предлагаешь, как чинить,
пока не спросят.

Порядок:
1. Прочитай docs/PLAN.md и docs/HANDOFF.md: задание текущей фазы и критерии.
2. Открой report.html последнего прогона и все картинки в папке проверки.
   Смотри глазами: кропы при 100% и ×5, карту разности с baseline,
   референс NASA рядом с showcase.
3. Пройди по критериям по одному: выполнен / не выполнен / выполнен
   формально, но глазами видно иначе. Последний случай — не принят.

Правила:
- Прямая граница на небе любой высоты видна глазу. «Ниже шума» её не оправдывает.
- Среднее по туманности не ловит выжигание: смотри фактуру и кроп core.
- Число в задании, которое режет больше ожидаемого, — стоп и вопрос.
- Отступление от задания допустимо, если объяснено и показано.
- Объяснение без проверки на данных — гипотеза, не вывод.
- Measured и showcase — разные цели; совпадение с NASA — ориентир только для showcase.
- Проверь, что кропы стоят на задуманных местах (core — на центральной звезде).

Ответ: вердикт одной строкой, затем по критериям, затем список того,
что владелец должен решить сам, с вариантами. Без похвалы и без пересказа.
```

Вызов: `@"acceptance (agent)" прими фазу 3i`. Вопросы вкуса (веса фильтров, насыщенность, `shadows`) приёмщик выносит владельцу, не решает сам.

## 8. Ошибки, которые уже сделаны и не должны повториться

- Направление параметров: `a` и бывший `lift` — «меньше — сильнее». Одна приёмка стыков прошла на слабом подъёме из-за этого.
- Все картинки до phase-3c были отражены по вертикали (нулевая строка FITS — низ). Поймано референсом NASA в соседней клетке. Тест есть.
- Кропы приёмки в 3g стояли не на месте после сужения кадра. Теперь RA/Dec и тест.
- Метрика скачков на швах в 3f была неверной (шум завышен плавным ходом фона); выводы 3f пересмотрены в 3g.
- Кеш не знал версию алгоритма и один раз молча отдал старую маску. Версии в ключах есть.
- Правило «≥ 4 экспозиций на краях» дано без карты числа экспозиций — отрезало 300 px. Карту смотреть до правила.

- NASA/STScI NIRCam Southern Ring: `data/reference/ngc3132_nasa.jpg` (AstroPix 2022-033b, 3000 px). Палитра там: F090W синий, F187N голубой, F212N зелёный, F356W жёлтый, F405N и F470N красные.
- Полный TIFF референса: `mast:OPO/product/STSCI-J-p22033b-f-4833x4501.tif`.
- Hubble-референс для 3b: пресс-релиз STScI-1998-39.
- Документация: NIRCam pixel scale 0,031″ SW / 0,063″ LW; i2d уровня 3 — мозаика, уровня 2 — отдельные экспозиции; единицы MJy/sr.
